# RCA — delhi-vascular-ir initial deploy

## Symptom
Deploy run `01d9cc13-5349-4000-8721-0f1f2e2f45d5` failed at step **build_image**, substep `frontend-build 13/13`:
```
[BUILD_LOG] [frontend-build] ERROR: No build or dist directory found
```

## Root cause (manifest, confirmed)
This is a **farm** template deployment (`farm_ts_react_mongo_base_image`, kubernetes frontend), but the frontend has been swapped to **Next.js 15**. `frontend/next.config.mjs` sets, for production builds:
```js
...(isProd ? { output: "export", trailingSlash: true } : {...})
```
Next.js static export (`output: "export"`) emits its artifacts into an **`out/`** directory. The frontend compiled fine in the real build ("✓ Compiled successfully in 15.4s"), but the template's artifact-copy step only recognized CRA's `build/` and Vite's `dist/` — not `out/` — so it exited 1.

Confirmed from source read in the eph sandbox: `frontend/package.json` (`"next": "15.5.4"`, `"build": "next build"`) and `next.config.mjs`. The failing `RUN` block in `Dockerfile.cloudbuild` (frontend-build stage) matched the build log exactly.

## Fix applied (manifest override, staged to GCS)
Wrote the complete manifest set (config.yaml + 5 template files) with minimal changes adding `out/` support:
- **Dockerfile.cloudbuild** (frontend-build stage, the step that failed): added an `elif [ -d "out" ]` branch copying `out/.` → `/frontend-output/`.
- **Dockerfile** (non-cloudbuild, for parity): added `elif [ -d "out" ] && [ ! -d "build" ]; then mv out build` to the dist→build normalization.
- **build-frontend-artifacts.sh**: added `out` to the BUILD_DIR selection.
- **nginx.conf**: `try_files` broadened to `$uri $uri/ $uri.html /index.html` to serve Next.js static-export nested routes (trailingSlash). entrypoint.sh unchanged.

These are staged on pending run `ec2c855e-8a33-462a-912a-e5549ea9f6ac` (dynamic_manifest=true) and will be adopted on the next redeploy.
